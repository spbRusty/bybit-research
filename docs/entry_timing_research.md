ALTERNATIVE ENTRY TIMING — ИССЛЕДОВАНИЕ
========================================
Дата: 2026-09-04
Статус: ТОЛЬКО ИССЛЕДОВАНИЕ, без реализации

1. ТЕКУЩИЙ МЕХАНИЗМ (baseline)
=============================
- Signal: свеча T проходит prefilter (relative_volume > 3.0 OR relative_range > 3.0)
- Entry:  open(T+1) — рыночный ордер на открытии следующей свечи
- Exit:   close(T+h) — закрытие через h минут
- Return: close(T+h) / open(T+1) - 1
- Cost:   0.20% round-trip

Ключевые свойства:
- open(T+1) ≈ close(T) (gap ≈ 0, std ≈ 0)
- Нет look-ahead: entry price известен в момент T
- MFE mean: +0.19% (5m), +0.48% (30m) — потенциал есть
- MAE mean: -0.19% (5m), -0.48% (30m) — риск эквивалентен

2. АЛЬТЕРНАТИВЫ (протестированы)
================================

2.1 CONFIRMATION ENTRY (вход после подтверждения)
--------------------------------------------------
Механизм: входить только если return_1m > 0 (для long).
Entry price: close(T+1) вместо open(T+1).

Результат:
  from open(T+1):  +0.001057  (выглядит хорошо)
  from close(T+1): -0.000030  (почти ноль!)

Вывод: вся "прибыль"confirmation = micro-structure эффект.
Первое минутное движение уже в цене входа. Задержка = нулевой alpha.

2.2 LIMIT ORDER (вход по лимитному ордеру)
-------------------------------------------
Механизм: limit order ниже open(T+1) на N bps.

Результат (limit at open - 0.05%):
  Fills (41%):     return_5m = -0.000768  (хуже baseline!)
  No fills (59%):  return_5m = +0.000530  (лучше baseline!)

Вывод: limit orders заполняются на СЛАБЫХ сигналах (где цена падает).
Сильные сигналы (где цена растёт) пропускаются.
Это антипаттерн: фильтруешь слабые, теряешь сильные.

2.3 TWAP (вход усреднением по времени)
----------------------------------------
Механизм: avg_entry = avg(open(T+1), ..., open(T+N))

Результат (TWAP over 2 candles):
  TWAP(2): -0.00000427  (хуже baseline -0.00000259)

Вывод: усреднение даёт худшую цену входа, потому что
средняя цена = open(T+1) + дрейф вниз.

2.4 VWAP (вход по средневзвешенной цене)
------------------------------------------
Механизм: VWAP = sum(price * volume) / sum(volume) over next N candles.

Не требует额外 данных — volume и price доступны.

Ожидание: аналогично TWAP, но с весом по объёму.
Нужно тестирование (пока не сделано).

2.5 SCALED ENTRY (вход частями)
---------------------------------
Механизм: 50% на open(T+1), 50% на open(T+2)

Результат: аналогичен TWAP — хуже единовременного входа.

2.6 ENTRY AT SPECIFIC PRICE LEVEL
-----------------------------------
Механизм: входить на определённом уровне (support/resistance).

Проблема: уровни нужно вычислять без look-ahead.
rolling_high/low из прошлого — ок, но это не Levels из orderbook.

3. ВЫВОДЫ
==========

3.1 open(T+1) ОПТИМАЛЕН для текущей модели.
    Любая задержка входа = худшая цена = меньший return.
    Это базовый micro-structure эффект: цена двигается в первые минуты.

3.2 Confirmation entry не работает.
    return_1m > 0 = micro-structure шум, не сигнал.
    Прибыль от фильтра съедается худшей ценой входа.

3.3 Limit orders — антипаттерн.
    Заполняются на слабых сигналах, пропускают сильные.
    Отрицательный selection bias.

3.4 TWAP/scaled entry хуже единовременного.
    Средняя цена хуже текущей open(T+1).

4. ЧЕГО НЕ ТЕСТИРОВАЛИ (требует дополнительных данных)
=====================================================

4.1 VWAP entry — требует volume данных по свечам T+1..T+h
    (volume доступен в events, но VWAP не вычислен)

4.2 Entry по best bid/ask — требует tick-level данные
    (orderbook есть как mk_best_bid/mk_best_ask, но это snapshot)

4.3 Entry по trailing stop — требует exit timing, не entry timing

4.4 Entry по order flow — требует real-time данные
    (mk_flow_imb доступен, но это прошлые данные)

5. РЕКОМЕНДАЦИЯ
===============

Сохранить текущий entry timing (open(T+1)) как baseline.
Исследовать EXIT timing как приоритетный направление:
- MFE >> return → есть потенциал для лучшего выхода
- Take profit / trailing stop / time-based exit
- Это изменит return_{h}m формулу, а не entry_price

Следующий шаг: исследовать alternative EXIT timing.
