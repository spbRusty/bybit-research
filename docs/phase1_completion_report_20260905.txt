## Feature schema (103 ob_* features + 4 provenance = 107 total new columns)

### Snapshot features (computed per snapshot)
| Feature | Formula | Nulls when |
|---------|---------|------------|
| `ob_spread_bps` | (ask1 - bid1) / mid * 10000 | never (base cols) |
| `ob_spread_abs` | ask1 - bid1 | never |
| `ob_imbalance_{N}` | (bid_vol_N - ask_vol_N) / (bid_vol_N + ask_vol_N) | total == 0 |
| `ob_depth_bid_{N}` | sum(bid_sz_1..N) | never |
| `ob_depth_ask_{N}` | sum(ask_sz_1..N) | never |
| `ob_depth_total_{N}` | bid_vol_N + ask_vol_N | never |
| `ob_vwap_bid_{N}` | sum(bid_px_i * bid_sz_i) / sum(bid_sz_i) | den == 0 |
| `ob_vwap_ask_{N}` | sum(ask_px_i * ask_sz_i) / sum(ask_sz_i) | den == 0 |
| `ob_top1_share` | bid_sz_1 / (bid_sz_1 + ask_sz_1) | total == 0 |
| `ob_top5_share` | sum(bid_sz_1..5) / sum(bid_sz_1..5 + ask_sz_1..5) | total == 0 |
| `ob_best_bid` | alias of best_bid | never |
| `ob_best_ask` | alias of best_ask | never |
| `ob_mid` | alias of mid_price | never |

Where N ∈ {1, 3, 5, 10, 20} from `depth_levels` config.

### Change features (delta over snapshots)
| Feature | Formula | Nulls when |
|---------|---------|------------|
| `ob_depth_change_{N}_{iv}` | diff(depth_total, iv) | first iv rows |
| `ob_spread_change_{iv}` | diff(spread_bps, iv) | first iv rows |
| `ob_imbalance_change_{N}_{iv}` | diff(imbalance, iv) | first iv rows |

Where iv ∈ {1, 6, 60} from `change_intervals` config.

### Volatility features (rolling std)
| Feature | Formula | Nulls when |
|---------|---------|------------|
| `ob_depth_volatility_{N}_{lb}` | rolling_std(depth_total, lb) | < lb rows |
| `ob_spread_volatility_{lb}` | rolling_std(spread_bps, lb) | < lb rows |
| `ob_imbalance_volatility_{N}_{lb}` | rolling_std(imbalance, lb) | < lb rows |

Where lb ∈ {5, 12, 60} from `lookback_snapshots` config.

## Exact temporal semantics

### Predictor features (get_predictor_features)
- Input: snapshots with `timestamp_ms <= T` (enforced by `get_pre_event`)
- Change/volatility features computed from those snapshots only
- **No forward leakage**: a predictor feature at time T uses only data from snapshots at or before T
- First `max(change_intervals)` + `max(lookback_snapshots)` rows will have null change/volatility features

### Response features (get_response_features)
- Input: snapshots with `timestamp_ms > T` (enforced by `get_post_event`)
- Used for dynamics analysis only — NOT for predictor features
- First rows will have null change/volatility features

### Change features
- `diff(iv)` is Polars default: `value[i] - value[i - iv]`
- First `iv` rows are null (no prior data to diff against)

### Volatility features
- `rolling_std(lb)` uses Polars default (unbiased, ddof=1)
- First `lb - 1` rows are null (insufficient window)

## Handling of gaps/missing data

1. **Gap detection**: BookState detects gaps when `update_id` skips. `gap_detected` column is boolean per snapshot.
2. **Post-gap invalidation**: After a gap, the reconstructed book state is invalid until a fresh snapshot arrives. `apply_delta()` returns false when `has_valid_state` is false → snapshot requested.
3. **Null propagation**: Features that depend on gap-affected data inherit nulls naturally through Polars null semantics.
4. **Zero-depth handling**: Division by zero → explicit null via `pl.when(total > 0).then(...).otherwise(None)`. No silent zeros in imbalance or VWAP.
5. **Missing snapshots**: If a symbol has no data for a date, `read_reconstructed()` returns None → empty DataFrame → no features produced.

## Provenance implementation

- `feature_version`: hardcoded "1.0" in source code
- `reconstruction_version`: from `orderbook_research.toml` config
- `snapshot_freq_sec`: from config (5 seconds)
- `config_hash`: deterministic hash of all config key-value pairs, allows detecting config drift between feature runs

All provenance columns are added as `pl.lit()` literals in `compute_all_features()`.

## Implementation notes

1. **Three-pass Polars batching**: `compute_snapshot_features()` uses three sequential `with_columns` calls because Polars does not guarantee column evaluation order within a single batch. Pass 1: base aliases + depth_bid/ask. Pass 2: depth_total. Pass 3: imbalance + VWAP + shares.
2. **tomllib.dumps removed**: Python 3.12's `tomllib` is read-only. Config hash uses sorted key-value string formatting instead.
3. **Parquet format**: Wide-format (one row per snapshot, 90 columns) instead of long-format (one row per level). Simpler downstream, but larger files.
